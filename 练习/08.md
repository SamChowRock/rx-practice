## 发散题 A｜长笛晚到，第一声应该落在哪一拍

指挥在第 1 刻举棒、第 10 刻收棒。举棒后每两刻敲一次，拍号从 1 数到 4 再循环；空场也照敲。大提琴从 0 刻在场，长笛第 4 刻加入，两人都在第 6 刻离席。客席第 8 刻进来，只听下一拍，不补听旧拍。

分别写下三位乐手听到的“时刻／拍号”，另记指挥敲过的每一拍。若每把椅子都有一台坐下才启动的节拍器，哪位乐手最早会发现拍号不对？客席入场时墙牌显示最近已敲的拍号，把它与客席实际听到的第一声作比较。

<details>
<summary>展开入拍谱，逐步搭出一只由指挥持棒的节拍器</summary>

找两种可以观察的动作。一种是敲击本身，声波过去后再坐到椅子上听不到它；另一种是某人已经坐好、接下来能够听。先不画人，只从举棒起每两格标记一次。得到第 3 刻敲 1、第 5 刻敲 2、第 7 刻敲 3、第 9 刻敲 4；下一声本该在 11，收棒早于它。空场出现在 [6,8)，第三拍落在其中，整张指挥谱仍有四声。现在在同一张纸上画椅子有人坐的区间，保留落在区间内的拍。大提琴听 3/1、5/2，长笛只听 5/2，客席只听 9/4。把三个人的谱叠起来也找不回 7/3，所以不要拿“所有人共听到几声”代替指挥敲了几声。

长笛是最短的失败样例。他在第 4 刻坐下，若这时打开自己的节拍器，两刻之后才响第一声，所得是 6/1。若他在同一刻先离座关机，那一声甚至不会进谱。正确谱要求第 5 刻听见第二声，离座与敲击的同刻先后对这一要求毫无影响。两只节拍器都能严格保持每两刻一响，问题在于从哪个时刻、哪个拍号起算。把它们调成相同间隔，只对齐了速度；把第一声晚了多少和它在小节内的位置也对齐，才得到同一次演奏。

```ts
const pulse$ = defer(() => {
  starts++
  return interval(2, clock).pipe(map(n => n % 4 + 1), finalize(() => stops++))
})
```

```ts
const baton = connectable(pulse$, { connector: () => new Subject<number>() })
const first = listen(baton, cello)
clock.schedule(() => {
  const performance = baton.connect()
  clock.schedule(() => performance.unsubscribe(), 9)
}, 1)
```

6 刻大提琴和长笛退订各自的句柄，指挥仍持有 performance。客席在 8 刻看到牌上是 3，耳朵要等到 9 刻才听到 4。

</details>

## 发散题 B｜桌游中途换座，接手的人可以知道什么

青、红轮流摸牌，青先。公共牌显示轮到谁、全桌已摸几张，每席只能看到自己的手牌。合法摸牌才摇铃，迟到的人听不到旧铃声。

1 刻青摸竹，2 刻红摸月。3 刻新人接青席，立即记公共牌和本席手牌，之后只记有变化的画面和现场铃声。4 刻红抢摸星，5 刻青摸松，6 刻红再摸星。7 刻裁判结算为 7 分，8 刻有记分员来问终分。列出新人的三份记录、早到和晚到的记分员所得分数，以及第 9 刻新桌的首张公共牌。

若新人只接旁观席，写出发牌员、裁判、各席和旁观者各拿哪些读写入口，使旁观者能听铃、看公共牌和查询结算，却拿不到手牌。

<details>
<summary>展开牌桌的三种交付、摸牌转移和换局边界</summary>

在桌面摆三只盘。公盘放一个轮次标识和一颗计数珠，青盘放青自己的字牌，红盘放红自己的字牌；铃拿在发牌员手里。当青摸“竹”，公盘从青／0 变成红／1，青盘多一张“竹”。红摸“月”，公盘变成青／2，红盘多一张“月”。第 3 刻换座的是人，桌上的盘与轮次没有清空。因此新人第一眼看见青／2、手中“竹”，从坐下那一刻开始听，耳朵里一声铃也没有。这三个答案不能由相同的“把上一项重发给新人”统一得到。

第 4 刻红伸手时公盘仍指青，发牌员拒绝。成功摸牌铃不能响，手牌不能新增，公盘不应翻动。若游戏还有“犯规罚分”规则，可把这次拒绝另记给裁判；题面只要成功摸牌的三份观察，记录里不多加动作。第 5 刻青摸松后公盘红／3，青看到竹、松两张，铃记青摸牌。第 6 刻红摸星后公盘青／4，铃记红摸牌，青的手牌没有发生变化。以**首次交付也要记、之后只在对应内容改变时再记**为本题的观察口径，三份记录分别为 [青／2，红／3，青／4]、[[竹]，[竹，松]]、[青摸牌，红摸牌]。若系统还会为红摸牌重画一次相同青牌，牌面看似正确，手牌通知却多了一项。

```ts
const old = state.value
if (ended || old.turn !== seat) return
const turn = seat === '青' ? '红' : '青'
const hands = { ...old.hands, [seat]: [...old.hands[seat], tile] }
state.next({ turn, count: old.count + 1, hands })
bell.next(seat + '摸牌')
```

```ts
publicBoard: state.pipe(map(b => b.turn + '/' + b.count)),
hand: (seat: Seat) => state.pipe(map(b => b.hands[seat]), distinctUntilChanged()),
sounds: bell.asObservable(), finalScore: result.asObservable()
```

结算用 AsyncSubject 写 7 后完成，场内和迟到的记分员都读到 7。开新桌创建新的牌面、铃和结算记录，从青／0 起步。发牌员负责写状态，裁判负责结算。旁观者只拿 publicBoard、sounds 和 finalScore，青席额外拿已经选定的青席手牌流。

</details>
