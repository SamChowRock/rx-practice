# 从一行日志到实时控制台

一本用 TypeScript 学 RxJS 7.8.2 的项目教程。假设你会写事件处理函数、读懂 Promise 和数组方法；不假设你用过 Angular，也不要求先背操作符。

第一次读，从[第 0 章《等下一行日志的时候》](book/00.md)开始。跟着一次正在编译的任务打开日志面板，再到第 1 章动手写它的关闭按钮。

## 五分钟跑通

在本目录打开终端。需要 Node.js 24（含 npm）；首次安装依赖需要联网，装好后所有章节和本地控制台均不需要外部服务。

```sh
node --version
npm ci
npm run lab -- 01
npm start
```

第三条只运行第一课。最后一条在前台提供本地服务；打开 [实时控制台](http://127.0.0.1:4173)，不要双击 HTML。关掉日志面板但保留错误计数，点击「检查服务端」：活跃连接应仍为 1。再关计数器，稍后重查应为 0。按 Ctrl+C 结束；若端口冲突，在 macOS/Linux 下用 `PORT=4180 npm start`。使用终端打印的 **127.0.0.1** 地址，服务不会对局域网开放。

## 怎样读章内的时序图

每章的「读图」都可以点开看大图。先遮住结果那一行，从左向右走过输入；遇到切换、关闭或失败时，先判断哪段工作还有资格交付，再揭开结果。纵向虚线把同一时刻对齐，圆点或圆角标签表示一次事件，带端线的横条表示一段持续的工作。刻度按标注读，图上的间距有时为容纳文字而压缩。

第一次可以从[第 6 章的 A、B 请求](book/06.md)开始，看旧请求如果活到第 40 毫秒，会怎样覆盖新结果。再看[第 12 章](book/12.md)，把两段订阅的左右端点分别译成测试中的 `^` 和 `!`。

从第 1 章起，每章有同编号的 TypeScript 实验，例如 [生命周期实验](labs/01.ts)；`npm run lab -- 06` 单跑第 6 章。第一次先读断言左边，遮住期望值。第二次把时间、事件顺序或结束方式改一处，**在运行之前**写下你预计哪条断言会失败。最后再恢复基线。不要用“测试原封不动变绿”代替做题。

**扩写版怎么读。** 初读先做章首题，带着自己的时间线读第一段实现；不要一次把所有变式做完。复习时反过来，从一个你解释不通的现象出发，选下面的一条路：

| 你在项目里看到的现象 | 回哪一章、带走什么证据 |
|---|---|
| 首行已经画出来，后台却还在解码整份历史 | [第 1 章](book/01.md)：把“交给面板的行数”和“生产端实际解码的行数”分开计。 |
| 两个订阅者拿到的“最新值”说不拢 | [第 8 章](book/08.md)：手画同步广播中嵌套输入的顺序，不要只比较最终状态。 |
| HTTP 已返回，第二个面板却读不到同一份正文 | [第 10 章](book/10.md)：确认共享的到底是 Response 还是已经解析的数据。 |
| 列表看起来是空的，导出的文件里却有行 | [控制台装配](book/控制台装配.md)：分别标出草稿、生效筛选、模型快照和最后一次绘制。 |
| 用户点确认的是 3、4 号座，发出去的却是 3、8 | [第 17 章](book/17.md)：固定同一采样时刻，只改变提交值是否继续引用可变草稿。 |

每条路的终点不是记住一个解释，而是找到一个**能让两个候选实现出现不同结果**的输入。能用自己的反例解释差别，再去做章末的跨章自测。

**想知道自己能不能把思路带离控制台？** 17 章共设了 39 道发散题，每章 2 至 3 道。选一道，先按题面给的输入和业务约定手算结果。再展开参考解法，找到决定那一刻输出的 TypeScript 语句，看哪条断言能区分你的方案和另一种写法。最后只改一个条件，重新预测并运行同章实验。[发散练习导航](发散练习导航.md)

```sh
npm run lab -- 07        # 日志控制台主线
npm run transfer -- 07   # 第七章的跨领域题
```

例如，定向赛的打卡记录可以先到终点、后到起点，过了裁判确认线才能发章；逐格皮影里，同一姿态连续踩两次踏板却必须留下两张相同底片。在[结业章](book/17.md#transfer-a)里，前者用代码区分“卡片抵达”和“允许盖章”，后者让你看到为什么可以对姿势状态去重，却不能把两次曝光合并。不是给原案例换名，而是检验原来的判断到哪里还成立。

- [控制台装配与逐章动手指南](book/控制台装配.md)：把章节里的小实验装回同一个程序，读懂成品并亲手制造故障。
- 前九章还可以运行 `npm run stage -- 5` 与 `npm run stage -- 6`，在同一输入下对照加上一个功能前后的控制台输出。
- [类型、成员与重载实验](book/声明也要会用.md)：学会从公开声明读出运行时行为的边界。
- [365 项 API → 正文、实验与声明](API-正文索引.md)：查某一项具体在哪一章学，以及 26 个重点分别在哪五章复习。**仅当你能解释并验证它时**，才到[个人清单](RxJS-7.8.2-API清单.md)打勾。
- [课程大纲](RxJS-教程大纲.md)：原定章节、闭卷题和覆盖口径。导出数按「入口 × 名称」计算，不把同义的重复导出说成两种技术。

## 按 Rx 的设计问题回读

如果已经会写 `pipe`，拿一个刚改过的需求从这里进。每次先试着让自己的设计出一次错，再看正文怎样解释这个结果。

| 设计时卡住的地方 | 用什么输入检验自己的想法 |
|---|---|
| [该记住多少历史？](book/04.md#如果只给你上一刻的答案你还能算出下一刻吗) | 两块徽标现在都是 1，下一行都是正常日志，其中一块却得归零。 |
| [该用谁的钟？](book/05.md#日志写于哪一秒浏览器收到它又是哪一秒) | 服务器第 9 秒产生的错误，第 12 秒才到浏览器。把它填进哪一格，取决于图的标题。 |
| [两个字段要不要拆成两条流？](book/07.md#两个字段来自同一次修改中间能出现半张新表吗) | 一份列表只更新一次，统计面板却短暂交出一组从未同时成立的数字。 |
| [哪些数据要有写入端？](book/08.md#哪些地方应该有权调用-next) | 一条正常日志挤走旧错误，没人按清屏，错误徽标也得减一。 |
| [消费太慢，压力传到哪里？](book/09.md#画面不再卡顿积压去了哪里) | 每秒收到 1000 行，只能写完 600 行。十秒后去哪里找其余 4000 行？ |
| [哪些失败可以重试？](book/11.md#能重新订阅是否就能把业务操作再做一次) | 同一笔备注已写入，确认却丢了。把重送一次与再点一次分别算账。 |
| [什么证据能推翻实现？](book/12.md#测哪一刻才有机会推翻自己的实现) | 两块屏幕都只显示 B，其中一块仍让 A 占着连接。 |
| [怎样把这些判断装回一个程序？](book/控制台装配.md#从一次断线推导整张订阅图) | A 等待重连时切到 B，然后依次关闭两块面板。逐拍决定哪条连接和哪个游标应当存活。 |

### 带着一次设计评审来读

第一次接手响应式代码，可以先看[日志面板怎样从两个输入推导画面](book/00.md#从收到后做什么走到画面依赖什么)，再对照[数组、Promise、异步迭代和 Observable 各替调用者解决哪一步](book/02.md#从调用者的座位看应该返回哪一种东西)。给网络接口定类型时，试着把“字节已传完”和“文件已受理”分别写成能被证实的消息。[上传进度与业务回执](book/10.md#请求的进度和结果能放进同一条流吗)

已经习惯 async/await 的读者，可以先猜一遍 [async 接收回调与来源完成的顺序](book/01.md#给-next-加上-async来源会等我写完吗)，再用 `npm run lab -- 01` 看“交付了两行”和“写完了两行”分别发生在什么时候。

如果评审的是一段已有管道，可以带以下三项改动去做实验。每次先写下你认为会保持不变的结果，再对照输出。

| 要评审的改动 | 决定两版是否等价的问题 | 实验 |
|---|---|---|
| 把解析提前到筛选之前 | 原来不会进入解析器的心跳，现在会发生什么？ | [第 13 章](book/13.md#凭什么说两段管道等价) · `npm run lab -- 13` |
| 把告警挪进画面订阅 | 晚到的详情页补读一行，值班室要不要再响一次铃？ | [第 14 章](book/14.md#重播一行日志要不要再响一次铃) · `npm run lab -- 14` |
| 把取消按钮接在队列外面 | 正在写的、等着写的、稍后才提交的三份文件分别该怎样？ | [第 15 章](book/15.md#把取消按钮交给哪一层) · `npm run lab -- 15` |

独立设计时还有三道取舍题。[控件与地址栏互相写回](book/16.md#两个控件互相写回应该在哪儿截断循环)要求后退不增加浏览历史，但重新加载同一任务仍有效；[场次各自的保存队列](book/17.md#加一条业务规则为什么要重画队列)要求 B 的修改可以越过慢速的 A，却不许 A 的两笔修改乱序；[接星星的争议回放](game/03-round.md#同一局能不能重演取决于记录了什么)要求先确定要检验碰撞规则还是按键处理，再决定录哪些输入。

## 给自己的学习记录

每次只记五行：① 我认为谁触发？② 它读取的是哪一刻的状态？③ 什么事件拥有终止/清理的权力？④ 哪个反例改变了我的判断？⑤ 下次不看提示，拿什么输出或订阅记录验收？不会时记**尚未区分的两种解释**，比记“没学懂”更有用。

卡住时按症状走：能输出但不会停 → 第 1、4、12 章；重新订阅后看到旧值 → 第 2、8、16 章；只在慢网络出错 → 第 6、10、11 章；知道函数名却写不出规则 → 第 7 章闭卷题，然后直接做第 17 章的需求变式。

## 验证与版本

```sh
npm run check
npm test
node tests/network.mjs
node labs/contracts.ts
```

类型检查包括实验中的反例（故意写错且必须被编译器拒绝）。测试执行模型断言、逐章实验和索引核验；真实网络实验只监听本机随机端口，需要允许本机回环连接。索引核验读取实际安装包的公开类型声明，检查章节定位；它不衡量个人掌握程度。用于复现的是锁文件中的 **7.8.2**，而不是对未来版本的预测。进一步追溯可查[官方 Observable 指南](https://rxjs.dev/guide/observable)、[虚拟时间测试](https://rxjs.dev/guide/testing/marble-testing)与[多播迁移说明](https://rxjs.dev/deprecations/multicasting)。
