# 21｜两份归档做一张报告，空的那一栏怎么填？

构建 A 留下两行，构建 B 顺利结束，归档一行都没有。点「比较」，预期是左栏 2、右栏 0。换成读不出来的构建 C，左栏仍该显示 2，右栏则要写「读取失败」。如果这两种情况都填零，读报告的人就会把一次故障当成一份干净的归档。

## 最后一份数组什么时候才能印？

上一章的 `rowsFor(build)` 成功时发出一份完整数组，然后完成。要生成一次包含左右两栏的报告，可以把这两个来源交给 `forkJoin`：

```ts
forkJoin({ left: rowsFor('A'), right: rowsFor('B') }).subscribe(report => {
  console.log(report.left.length, report.right.length)
})
```

这里传对象，收到的结果也带 `left`、`right` 两个名字。假设左栏先交卷，`forkJoin` 会把它最后发来的值留下来，继续等右栏。某一栏如果交过两版，只取最后一版。要确定哪版算最后一版，还得等它说「读完」。

在项目根目录运行 `node`，亲手把右栏的交付与结束分开：

```js
const { of, Subject, forkJoin } = require('rxjs')
const right = new Subject()
forkJoin({ left: of(['开始编译', '缺少入口文件']), right }).subscribe({
  next: report => console.log('生成报告', report.left.length, report.right.length),
  complete: () => console.log('结束')
})
right.next(['甲'])
right.next(['甲', '乙'])
```

到这里还没有输出。左栏早已完成，右栏已经给过两项，却还可能送来第三版。现在输入 `right.complete()`，才会先看到「生成报告 2 2」，再看到「结束」。如果想在右栏每次更新时都重新画预览，两边有首值之后就可以算，用第 7 章的 `combineLatest` 更贴近那个需求。[第 7 章 · 谁来触发更新](07.md)

## 为什么把空数组换成 EMPTY，整张报告都消失了？

留在刚才的提示符里，分别运行下面两次读取。左栏相同，只换右栏：

```js
const { EMPTY } = require('rxjs')
function printWith(right) {
  forkJoin({ left: of(['开始编译', '缺少入口文件']), right }).subscribe({
    next: report => console.log('生成报告', report.left.length, report.right.length),
    complete: () => console.log('结束')
  })
}
printWith(of([]))    // 生成报告 2 0，然后「结束」
printWith(EMPTY)     // 只打印「结束」
```

`of([])` 调了一次 `next`，交的那份答卷上写着「零行」。`EMPTY` 直接完成，右栏从头到尾没有交过任何值。在本书使用的 7.8.2 中，只要有一路以这种方式结束，`forkJoin` 就无值完成。它无从替右栏决定该填 0、填「未记录」，还是取消这份报告。

再回看归档读取。第 19 章翻到末页时，`expand` 把 `EMPTY` 用在「下一页」的位置，刚刚到手的末页仍会向下交付。第 20 章把行交给 `toArray()`，哪怕一次行都没收到，只要归档正常读完，它也会发出一个空数组。所以真正的空归档本来就能得到右栏 0。把整个 `rowsFor('B')` 替换成 `EMPTY`，改动的是报告要收的那一栏。

## 右栏掉线，左栏还要不要等？

再看 C。它的 HTTP 读取报错，就连「归档到底有几行」也不知道。若让 error 直接抵达 `forkJoin`，整个订阅就会出错，仍在途的另一栏也会被退订。在总报告后面接一个 `catchError` 可以显示「比较失败」，但这时已经拿不到一张含左右两栏的结果。

要保留健康的一栏，先规定每一栏能交什么，再组合。成功的栏带行数，失败的栏只带状态：

```ts
function column(rows: Observable<string[]>) {
  return rows.pipe(
    map(list => ({ status: '已读完' as const, count: list.length })),
    catchError(() => of({ status: '读取失败' as const })),
  )
}

forkJoin({ left: column(rowsFor('A')), right: column(rowsFor('C')) })
  .subscribe(report => console.log(report))
```

C 的读取照样失败。`catchError` 随即改订阅 `of(...)`，由它发出「读取失败」这一项并完成。这样右栏有了能填进报告的值，`forkJoin` 会继续等 A 读完。若把回调缩成 `() => EMPTY`，虽然也处理了异常，右栏又成了没交答卷的那一路。

运行 `npm run lab -- 21` 可以看见这两份报告。A 对 B 的右栏有 `count: 0`；A 对 C 的右栏只有失败状态。实验还让右栏先报错、左栏稍后才回，分别检查保留下来的订阅和最终报告。在实际界面中，可以只对带 `count` 的栏显示数字，两栏都读完时再计算差值。[本章实验](../labs/21.ts)
