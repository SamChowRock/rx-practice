# 19｜读构建归档：中间一页是空的，还翻不翻？

控制台里的构建 A 已经结束。点「读归档」，列表只画出一行「开始编译」。同事却记得最后一行是「缺少入口文件」。打开请求记录，第一页之后确实又读了一页，第二页有零行。问题出在这里：这次读取凭什么知道已经翻到底了？

## 先把服务器的三封回信摆出来

归档接口一次返回一个对象。这里的 `rows` 只收录允许展示的日志，`next` 是服务器给下一次读取的游标。某一页的行都被隐藏，就可能拿到这样的第二封回信：

| 请求用的游标 | 收到的 rows | 收到的 next |
|---|---|---|
| `start` | `['开始编译']` | `'k7'` |
| `k7` | `[]` | `'m2'` |
| `m2` | `['缺少入口文件']` | `null` |

沿着最右一列读。第一页到手，才知道下次该传 `k7`；第二页虽然没字可画，手里却已经有了 `m2`。第三页恰好相反，有一行要画，已经没有下一页。用普通的 `await` 同样能写清这个循环：

```js
let cursor = 'start'
while (cursor !== null) {
  const page = await fetchPage(cursor)
  drawRows(page.rows)
  cursor = page.next
}
```

要接回控制台，页面希望把每一页交给已有的管道，还希望关窗时一并退出正在等待的读取。于是让 `readPage(cursor)` 返回一个 Observable，订阅时取这一页，成功时发出一个页对象并完成。一次请求读完，整个归档可能还差好几页。

## 把一页变成下一次读取

第 6 章的 `map` 会把每个输入变成一个输出。这里有一步它做不了：第二个游标来自**第一次请求的结果**，第三个游标又来自第二次的结果。RxJS 的 `expand` 允许返回的结果再次进入同一个函数。下面是[实验共用的翻页函数](../labs/archive.ts)：

```ts
function pagesOf(readPage: (cursor: string) => Observable<Page>) {
  return defer(() => readPage('start')).pipe(
    expand(page => page.next === null ? EMPTY : readPage(page.next), 1),
  )
}
```

`defer` 把首页的调用留到订阅时。首页抵达，`expand` 先把这个页对象交给下游，再用它的 `next` 去调用 `readPage('k7')`。这次调用返回的是一个可以订阅的来源；等它交出第二页，`expand` 会用同样的办法读 `m2`。第二个参数 1 限制同时展开的内层分支数。本例每页只给一个后继，也没有预先算好的页码可以并发去取。

到第三页，列表先拿到「缺少入口文件」。随后投影函数看到 `null`，返回 `EMPTY`。这个 Observable 一经订阅就完成，没有新的页对象可以再拿去翻页。相反，把 `takeWhile(page => page.next !== null)` 接在页流后面，第三页自己就通不过条件，里面那条报错也会被挡掉。

## 哪一步可以拆掉页对象？

翻页时要保留游标，画列表时只需要行。把拆页放在 `expand` 下游就行：

```ts
const rows = pagesOf(readPage).pipe(
  concatMap(page => from(page.rows))
)
```

处理第二页时，`from([])` 立即完成，这次没有行送给列表。`concatMap` 还在等上游交出第三页。于是同一次运行里，观察页数的人看到每页行数 `[1, 0, 1]`，观察行的人看到「开始编译」「缺少入口文件」。两边都收全了自己订阅的东西。

也可以在项目根目录运行 `node`，直接给翻页函数换一份回信。下面这份归档只有首页，而且它正好有一行：

```js
const { pagesOf } = require('./labs/archive.ts')
const { of } = require('rxjs')
pagesOf(cursor => {
  console.log('请求', cursor)
  return of({ rows: ['只有这一行'], next: null })
}).subscribe(page => console.log('读到', page.rows))
```

屏幕上有一次「请求 start」和一次「读到」。末页也可以是首页。这里和前面的循环都假设服务端给出的游标最终会到达 `null`。如果它把 `m2` 又指回 `k7`，两种写法都会继续翻；要识别坏归档，可以在一次读取里记下已经请求过的游标，第二次遇到同一个就报告异常。

在项目根目录运行 `npm run lab -- 19`。实验最后把第二页的回信扣住，先关窗，再让它送出 `m2` 游标。请求记录停在 `start、k7`，第三次读取没有启动。换回真实网络时，第二个请求能否同时中止，还要看 `readPage` 有没有把退订接到传输层。[第 10 章的读体与取消](10.md) · [本章实验](../labs/19.ts)
