# 20｜两块面板共读归档，导出为什么只剩最后一页？

列表从归档 A 读到了「开始编译」和「缺少入口文件」，等它读完再点导出，文件里却只有后面那条。服务端的请求次数完全正确：三个游标各取了一次。这条线索把问题缩小了。读取没有重复，得看看第二个读者拿到的那**一个值**究竟是什么。

## 缓存的一项有多大？

先把中间那张空页拿掉，只用两份各有一行的数组复现这个问题。列表从头订阅，导出晚一步。可以直接在项目根目录的 `node` 提示符里运行：

```js
const { of, shareReplay } = require('rxjs')
const saved = of(['开始编译'], ['缺少入口文件']).pipe(
  shareReplay({ bufferSize: 1, refCount: true })
)
saved.subscribe(page => console.log('列表追加', page))
saved.subscribe(page => console.log('写入文件', page))
```

列表打印两次，文件只打印一次。`shareReplay` 里的数字 1 按上游的 `next` 次数计数。第一页是一项，第二页又是一项；即使第一页装着一百行，第二页抵达时也会把它整个替换。把 1 改成 2 刚好能导出这个例子。归档若有第三页，同样的问题又会出现。

导出要的是一份**已经读完的归档**。沿用上一章的 `pagesOf`，可以先把各页拆成行，再在来源完成时用 `toArray()` 把所有行作为一个数组发出：

```ts
const rows = pagesOf(cursor => readPage('A', cursor)).pipe(
  concatMap(page => from(page.rows)),
  toArray(),
  shareReplay({ bufferSize: 1, refCount: true }),
)
```

现在存在回放区里的那一项是 `['开始编译', '缺少入口文件']`。代价也能从代码里看出来：末页迟迟不回来，`toArray` 就一直收着已读的行，列表也得等。这里做的是有限归档的整份预览。如果界面要求先画第一页，两块面板可以订阅逐页更新的累计列表；那时每次发出的数组都要能单独还原已经画出的内容。[第 4 章的 scan 与完成](04.md)

## 两次写了相同的管道，会共用什么？

列表调用 `rowsFor('A')`，导出也调用 `rowsFor('A')`。若函数体每次都重新执行上面的 `.pipe(..., shareReplay(...))`，系统里就有两个回放区。两个调用传了相同的字符串，RxJS 也不知道它们指的是同一份归档。

让这张归档页持有一张 Map。下面是两块面板拿到读取入口的过程；`archives` 在创建归档页时分配一次，收起某一块面板时仍在。[完整的 archiveReader](../labs/archive.ts)

```ts
const existing = archives.get(build)
if (existing) return existing

const rows = pagesOf(cursor => readPage(build, cursor)).pipe(
  concatMap(page => from(page.rows)),
  toArray(),
  shareReplay({ bufferSize: 1, refCount: true }),
)
archives.set(build, rows)
return rows
```

第一次调用只把 Observable 放进 Map。列表调用 `subscribe` 才去读 A；导出进来时取到同一个 Observable，接上已经在进行的读取。换成 B 则会创建 B 的入口。实验用已结束的构建编号作键，假设每个编号对应一份固定内容。若同一构建可以按不同条件导出，键也得把会改变结果的条件算进去。

## 在末页回来以前关窗

运行 `npm run lab -- 20`。实验恢复第 19 章的三页，让 A 的末页停下来，等列表和导出都订上以后，先关列表。此时还剩导出这一位读者，末页继续读。等它正常完成，文件拿到两行；列表随后重开，也立刻拿到两行。整段请求记录始终是 `A/start、A/k7、A/m2`。[实验源码](../labs/20.ts)

顺着这一遍的订阅数走，很容易找到末页归谁管：

```text
列表打开     0 → 1    读过首页和中间的空页，开始等末页
导出打开     1 → 2    继续等同一个末页
列表关闭     2 → 1    仍有人要写文件，继续读
末页读完               交付整份数组，导出完成
列表重开               从已完成的回放区取出数组
```

再把时机提前，让两位读者都在**首页仍未返回时**退出。`refCount: true` 会在读者数降到零时退订还活着的上游。Map 里虽然还是同一个入口，下次打开却要重新订阅，`defer` 又从首页开始。实验这次打印 `A/start、A/start`。两次运行的差别在于最后一个人离开时，读取究竟还在进行，还是已经成功完成。对于这份配置，RxJS 7.8.2 会保留正常完成的回放结果。
